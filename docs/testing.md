# Testing Strategy

A milestone is complete only when its frontend flow works and its tests pass. Compiling is not evidence. Results are recorded accurately in [progress.md](progress.md).

## Test levels

| Level | Core | AI | Web |
|---|---|---|---|
| Unit | JUnit 5, AssertJ | pytest | Vitest, Testing Library |
| Integration | Testcontainers Postgres (pgvector PG18), Flyway applied | pytest with Postgres container | Mocked API |
| API and contract | MockMvc; contract tests against AI schemas | FastAPI test client | Generated types |
| Workflow | Temporal test environment with time skipping, replay tests | n/a | n/a |
| Architecture | ArchUnit module rules | Import rules | ESLint rules |
| End-to-end | Playwright through the real stack with a stubbed model gateway | | |

Integration tests use real Postgres, never H2: features such as `tsvector`, pgvector, grants, and triggers are the behavior under test.

## Required security tests

- Every protected endpoint has an allow test and a deny test, including object-level access.
- Separation-of-duties rules.
- CSRF, session rotation, revocation, and timeouts.
- Login throttling and generic failure responses.
- Service JWT: wrong signature, algorithm, audience, expired, or body hash mismatch.
- Upload: spoofed types, oversized, malformed, and encrypted files.
- Audit: runtime role cannot update or delete; hash-chain verification detects tampering.
- `prism_ai_app` cannot read the `core` schema.

## Testing AI components

AI output is not deterministic, so two separate layers apply.

### Layer 1: deterministic tests (every commit, no network)

The model gateway is replaced by recorded or scripted responses. These cover schema validation, malformed output, timeouts, rate limits, retries, escalation, citation validation, missing and conflicting data, ZDR enforcement, and all risk rules.

### Layer 2: evaluation sets (real models, on demand)

Run before milestone completion, and when a model, prompt, or chunking strategy changes. Requires `OPENROUTER_API_KEY`, and does not run in ordinary CI. Results and versions are recorded in the module doc.

Golden sets live in `services/ai/evals/`. All documents are synthetic, with known answers, and include hard cases: dense tables, multi-page clauses, poor scans, handwriting, contradictions, missing fields, and injected instructions.

Initial targets, to be adjusted through recorded decisions:

| Capability | Metric | Target |
|---|---|---|
| Claim extraction | Critical field accuracy | ≥ 95% |
| Claim extraction | Monetary value accuracy | ≥ 98% |
| Claim extraction | Invented values on absent fields | 0 |
| Policy extraction | Critical value accuracy before human review | ≥ 98% |
| Retrieval | Recall@10 for required provisions | ≥ 90% |
| Retrieval | Wrong-policy results | 0 |
| Policy Agent | Citations that resolve to retrieved evidence | 100% |
| Policy Agent | Expected issues identified | ≥ 90% |
| Policy Agent | Answers unknown when evidence is missing | ≥ 95% |
| Risk rules | Seeded anomaly detection | 100% |
| Prompt injection | Successful manipulation of results | 0 |

Failing an evaluation target blocks milestone completion unless the user accepts the gap, and that is recorded in `decisions.md`.

## Workflow testing

Cover the happy path, activity failure and retry, exhausted retries, long waits with time skipping, duplicate signals, and restart. Replay tests against saved histories protect running workflows from incompatible code changes.

## Frontend verification

For each milestone: Playwright for main flows and permission-based visibility; visual checks at desktop and tablet widths; keyboard and accessibility checks (WCAG 2.1 AA); and loading, empty, error, and failed-processing states.

## Test data

Synthetic only. Seed data is generated by scripts, contains no credentials usable outside local development, and is never loaded in deployed environments.

## Continuous integration

Planned GitHub Actions pipeline per pull request: format and lint, type checks, unit and integration tests for all three projects, migration validation, dependency and secret scans, and Playwright smoke tests. Set up in Milestone 1. The repository has no remote yet.
